# Layer 3 Dashboard Documentation (Day 14)

## 1. Purpose

The Day 14 frontend (`frontend/`) is a read-only security review dashboard served locally alongside `firewall_server`. It presents:

- **Overview** – aggregate statistics, top reason codes, approval outcomes, and an audit chain verification trigger.
- **Sessions list** – paginated table of agent sessions.
- **Session detail** – vertical event timeline with live event-type / action / tool filters.
- **Reason-code glossary** – searchable, categorised descriptions of all 48 reason codes.

> [!IMPORTANT]
> The dashboard displays strings that originate from attacker-controlled content (tool names, reason code details, evidence summaries). **Every string from the API is treated as hostile data** and passes through `SafeText` or `IdText` before rendering.

---

## 2. Security Design

| Property | Implementation |
|---|---|
| **Token storage** | Memory-only variable in `src/api/token.ts`; never `localStorage`, `sessionStorage`, cookies, IndexedDB, or URL params |
| **Idle timeout** | 15-minute inactivity timer (mouse/key/scroll/click resets); on expiry token is wiped and user is redirected to login |
| **XSS prevention** | `SafeText` replaces C0/C1 control chars (except `\n`/`\t`), bidi override/isolate chars (U+202A–202E, U+2066–2069), zero-width chars (U+200B–200F), and BOM (U+FEFF) with `⟦U+XXXX⟧` markers; CSS `unicode-bidi: isolate` on every output |
| **CSP** | Production Vite build injects a strict `Content-Security-Policy` meta tag: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self' http://127.0.0.1:* http://localhost:*; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` |
| **Remote network** | Client validates base URL hostname at startup and before every request; rejects non-loopback hosts (unless `VITE_ALLOW_REMOTE_API=1` for development proxies) |
| **Fetch hardening** | `credentials: "omit"`, `cache: "no-store"`, `referrerPolicy: "no-referrer"`, 10-second `AbortController` timeout, 5 MB response body cap |
| **No CDN** | All JS/CSS assets are bundled locally by Vite; no remote fonts, icons, analytics, or CDN scripts |

## 5. Development

```bash
# Install (network required; uses node_modules/ which is git-ignored)
cd frontend
npm install

# Dev server (loopback only: http://127.0.0.1:5173)
npm run dev

# Point at a running firewall_server:
# Enter http://127.0.0.1:8000 as Server URL and your viewer token.

# Full check: lint + typecheck + test + build
npm run check

# Individual steps
npm run lint
npm run typecheck
npm run test
npm run build
```

```bash

python scripts/export_openapi.py       # → frontend/src/api/openapi.json
python scripts/export_reason_codes.py  # → frontend/src/data/reason_codes.generated.json
```

## 6. API Integration

The frontend uses the **viewer** role token only. Endpoints consumed:

| Endpoint | Page |
|---|---|
| `GET /health` | Login verification |
| `GET /api/v1/summary` | Login verification + Overview |
| `GET /api/v1/sessions` | Sessions List |
| `GET /api/v1/sessions/{id}` | Session Detail (header) |
| `GET /api/v1/sessions/{id}/events` | Session Detail (timeline) |
| `GET /api/v1/audit/verify` | Overview (manual trigger) |

All requests go through `src/api/client.ts` which enforces: loopback-only host, `Bearer` auth header, `credentials: "omit"`, `cache: "no-store"`, `referrerPolicy: "no-referrer"`, 10 s timeout, 5 MB body cap, and runtime shape validation.
